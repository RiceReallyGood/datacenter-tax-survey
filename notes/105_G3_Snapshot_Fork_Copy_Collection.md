# G3 合集：快照恢复、fork、硬件脏页跟踪、内存拷贝服务（Spice、Async-fork、PML、Copier、HDBSS 补丁）

> 用途：新文档 G3 节"暂停恢复与 spawn 税"的输入。论文四篇（F27–F30），网络资料一份。

## 1. Taming Serverless Cold Starts Through OS Co-Design（Spice，arXiv 2509.14292，MIT CSAIL Adam Belay 组，`F27`）
- 主流观点认为亚毫秒冷启动必须把状态常驻内存；论文指出**从磁盘恢复慢的根因是 OS，不是存储速度**：现有快照恢复要么逐片恢复、代价高，要么捕获了太多状态；OS 暴露的内存原语难以可靠地把数据预取进来、避免运行时缺页。
- Spice 与 OS 深度集成：直接恢复内核状态（不重放），提供专门恢复内存映射的原语。从磁盘冷恢复接近暖启动；时延比最好的进程级方案快最多 14.9 倍、比 VM 级方案快 10.6 倍。
- 启示："把空闲沙箱全部卸到磁盘、需要时毫秒级拉回"是可行的——这样"每兆瓦沙箱数"就不再受常驻内存限制，改为受存储带宽和恢复路径（缺页、页表建立）限制。

## 2. Async-fork（PVLDB 16(5)，2023，上海交大 + 阿里，`F28`）
- Redis 这类内存 KV 存储用 fork 做时间点快照，fork 期间父进程在内核里、停止服务，造成查询尾延迟尖刺；**fork 的执行时间主要花在复制页表上**。
- Async-fork 把复制页表的工作从父进程挪给子进程，并做主动同步保证一致性；已在阿里云公有云的 Redis 上部署。快照期间到达的查询，尾延迟降低 81.76%（8 GB 实例）和 99.84%（64 GB 实例）；64 GB 实例上父进程完成 Async-fork 只需 0.61 ms（此前最好的优化是 1.1 ms）。
- 启示：进程越大，fork 越贵，而且贵在页表复制——对应纪要"降低 spawn 税"。Linux 社区还有"页表写时复制"的补丁系列（2023 年到 v5，未合入）。硬件上相关的是：页表项批量复制的带宽、fork 后把可写页改只读需要的 TLB 失效（TLBIRANGE/TLBID）、之后写时复制缺页的进出内核时延。

## 3. Intel Page Modification Logging 研究（arXiv 2001.09991，2020，`F29`）
- 传统的页跟踪靠清掉 present 位制造缺页，代价很大：对 1 GB 的 VM 每秒清一次，合成负载最多慢 96.22%；VMware 为此只抽样 100 页，结果不准。
- Intel PML（Broadwell 起，与 VMware 合作）：MMU 在页表遍历中置 EPT 脏位时，把 guest 物理地址记进内存里的日志（512 项），满了才产生 VM 退出。在 Xen 上测：不增加功耗；热迁移和检查点时间最多缩短 10.18%；对应用的干扰最多再降 0.95%。缺点：只记写、不记读；满缓冲区的 VM 退出要由 VM 自己的 CPU 处理。论文提出 PRL（页引用日志）扩展以同时记录读。
- 启示：**Arm 的 HDBSS 是 PML 的对应物**（硬件把变脏的页记进缓冲区），HACDBS 更进一步（硬件批量把页清回干净，这一步 PML 没有）。x86 上 PML 的收益量级（迁移/检查点时间 −10% 左右）是保守的参考；在高频检查点的 Agent 沙箱（[90]：100 个沙箱每秒 17 个检查点请求）上收益应当更大，需要实测。

## 4. How to Copy Memory? Coordinated Asynchronous Copy as a First-Class OS Service（Copier，SOSP 2025，上海交大 IPADS + **华为**，`F30`）
- 把内存拷贝做成 OS 服务：应用可以让计算和拷贝重叠；服务统一调度 SIMD（AVX、SVE/NEON）和片上 DMA 两种拷贝单元（把 DMA 任务"搭车"在 AVX 任务旁并行执行，不空等 DMA 完成）；有全局视角做整体优化。Redis 最多快 1.8 倍，比 zIO 高 1.6 倍；已集成进 **HarmonyOS 5.0**。论文指出 Linux 内核因上下文切换代价不用 SIMD 拷贝，而 DMA 对小拷贝又不划算。
- 启示：与纪要的 MOPS（memcpy/memset 专用指令）和"DPA 卸载"都相关：小拷贝靠指令（MOPS 让 CPU 按微架构最优方式搬），大拷贝靠 DMA 引擎（鲲鹏上是 DPA；2026-09-29 更正：不是 cdma，cdma 是 UB 上的单边访存软件接口），两者由 OS 统一调度。这是华为自己的工作，可以直接引用。

## 5. 网络资料：FEAT_HDBSS/HACDBS 的 KVM 补丁（LWN 1047403；2025-11 v2、2026-02 v3、2026-07 v4）
- HDBSS（Armv9.4 起可选）：目标是降低"找出哪些页脏了"的成本、同时尽量不影响"记录页变脏"本身，让热迁移对 guest 和 host 的开销都比写保护或扫描 stage 2 页表低。KVM 提供 `KVM_CAP_ARM_HW_DIRTY_STATE_TRACK`，QEMU 在迁移前后开关；启用后硬件观察到"干净→脏"的转换就把页记入 HDBSS 缓冲区；同步脏页日志时 KVM 踢所有 vCPU 退出，把缓冲区内容合并进用户态可见的脏页位图。
- HACDBS（Armv9.4 起可选，依赖 HDBSS 与 HAFDBS）：硬件把 stage 2 描述符从"可写且脏"批量改成"可写且干净"；需要一个完成或出错时触发的 PPI 中断（HACDBSIRQ），目前 ACPI 表里还没有上游的声明方式。"KVM Dirty-bit cleaning hw" 补丁 2026 年 4–7 月到 v3。
- 启示：软件栈正在就绪（2026 年内可能合入），960 若支持，欧拉可以同步跟进；客户要这两个特性，用途是 CubeSandbox 的快照、暂停恢复和热迁移。
