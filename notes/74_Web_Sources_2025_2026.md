# 网络资料合集（2025–2026）：vLLM V1、SGLang v0.4、MCP 规范、Claude Code 沙箱、vLLM on Arm/SME2、Intel IAA zswap

| 来源 | 要点 | 对洞察的用处 |
|---|---|---|
| **vLLM V1 alpha**（vllm.ai 博客，2025-01） | V0 在 GPU 前向之间做 API 服务、调度、输入准备、detokenize、流式回传；"GPU 越快 CPU 开销越显眼"，Llama-8B@H100 的 GPU 步只有 ~5 ms。V1 用多进程把 tokenize/多模态/detokenize/流式挪出核心循环（EngineCore 只做调度 + 执行），**吞吐最高 +1.7×（归因于全栈 CPU 开销削减）**；前缀缓存在 0% 命中时吞吐损失 <1%（V0 显著） | 税表 #10：2025 年的软件基线；"多进程 + 重叠"= 需要更多核而不是更快的核 |
| **SGLang v0.4**（lmsys 博客，2024-12） | 零开销批调度器：CPU 提前一步准备下一 batch（调度、内存分配、前缀匹配/radix cache 操作），GPU 始终忙；+1.1× vs v0.3，小模型/大 TP 收益最大；缓存感知负载均衡命中率 20%→75%、吞吐 1.9×；XGrammar 结构化输出快 10× | #10、#6（radix cache 操作是 CPU 侧分配/查找税）；会话亲和路由（SMetric [67]）的工程版 |
| **MCP 规范 2025-06-18 · Transports** | 消息 = **JSON-RPC 2.0、UTF-8**；stdio 传输按换行分隔、子进程模型；Streamable HTTP：**每条客户端消息一次新的 HTTP POST**，服务端可用 SSE 流式返回，`Mcp-Session-Id` 会话头，Last-Event-ID 断线重放；二进制内容（图像/音频）在内容块中以 base64 承载（协议 schema） | 税表 #2/#7：Agent 工具调用的协议成本 = 每消息一次 HTTP 请求 + JSON 编解码 + base64（+33% 体积与编解码 CPU）；没有二进制帧或批量 |
| **Claude Code 沙箱**（Anthropic 工程博客，2025；sandbox-runtime 开源） | **进程级 OS 沙箱**而非容器/VM：Linux bubblewrap（+ seccomp）、macOS Seatbelt；文件系统限制在工作目录；网络经 Unix socket 走外部代理做域名白名单；"避免了启动与管理容器的开销"；内部数据：权限提示 −84%。Claude Code on the web 在隔离的云沙箱中运行、凭据外置。OpenAI Codex 本地同样用 Seatbelt/bubblewrap（+ Landlock/seccomp） | 争议 2 的部分答案：**本地 Agent 已走轻量进程级隔离，云端仍是容器/microVM**；对鲲鹏，沙箱税分两档：本地端（seccomp/namespace 成本，几乎无创建税）与云端（[51][64][57] 的 VM/容器税） |
| **vLLM on Arm CPUs**（vllm.ai 博客，2026-07） | Neoverse V2 上 CPU-only 服务：BF16 用 BFMMLA、INT8 用 SMMLA（oneDNN JIT，SVE128/256）、INT4 用 KleidiAI 微核；相对 2025-10 基线：BF16 2.7×、W8A8 4.8×（TPOT 5.7×）、W4A8 6.2×（TPOT 7.8×）；**mimalloc 替换默认分配器：离线吞吐 2.3×**；OpenMP 同步 +9%、prepacking +16%、paged attention 4× | 4.1 SIMD 行：Arm 服务器核已能做 CPU-only 小模型推理；**分配器税（#6）在 AI 栈上真实且大（2.3×）**——[35] 的结论在 Arm + PyTorch 上重现 |
| **Arm SME2 / KleidiAI / Arm AGI CPU**（arm.com、newsroom，2026） | SME2（Armv9.2）tile 寄存器外积 GEMM，KleidiAI 自动分派，"最高 6× 推理、2× 能效"（面向端侧）；2026-03 Arm 发布自研 AGI CPU（136 个 Neoverse V3 核）；SGLang/vLLM 已接入 Neoverse | 4.1 →960：SME2 级矩阵扩展的生态已就绪，服务器侧落地由 V3 后代承担 |
| **Intel IAA + zswap**（Intel 白皮书、Linux 6.8+ iaa-crypto、2026 批量压缩补丁） | IAA 做 zswap 的 deflate：30 进程/64K folio 场景吞吐 +62%、sys 时间 −28%；PMD folio +67%/−23%；内核 6.8 起驱动入主线，2026 年补丁做压缩批处理 | 4.2：内存侧压缩（把冷页压在内存里）是 KAE zip 在 AI 状态层的一个**现成**用法——"活着但空闲"的会话状态（2.3.7）正是 zswap 的对象 |
